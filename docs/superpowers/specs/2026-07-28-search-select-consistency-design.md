# 全局可搜索下拉框一致性设计

## 目标

统一系统内“搜索并选择”类下拉框的搜索、异步加载和表单保存行为，解决以下问题：

- 不同页面分别按 `value`、`label` 或默认规则搜索，结果不一致。
- 筛选或级联选择触发请求时，选项和页面内容短暂清空，造成闪烁。
- 异步选项刷新期间已选项标签消失，用户误以为选择没有保存。
- 上游字段变化时，部分页面会清空无关字段，部分页面又保留无效的下游选择。

## 方案比较

### 方案 A：共享选择器 + 保留查询上一帧（采用）

新增一个基于 Ant Design `Select` 的薄封装，统一本地搜索规则，并只在异步选项暂时缺失时保留当前已选项。对于筛选会改变查询键的页面，React Query 使用上一份数据作为占位，避免整个内容区被卸载。

优点是修复集中、兼容现有表单值结构、不增加依赖；缺点是需要把现有动态实体选择器逐步替换为共享组件。

### 方案 B：逐页补齐属性

在每一个 `Select` 上分别增加 `showSearch`、`optionFilterProp` 和加载处理。

改动看似直接，但重复代码多，后续很容易再次出现行为分叉，因此不采用。

### 方案 C：统一服务端搜索接口

所有下拉框都改成远程搜索和分页。

适合单个候选集达到数千条后的场景；当前数据规模没有必要，会扩大前后端改动和请求数量，因此暂不采用。

## 组件设计

新增 `SearchSelect` 组件，保持 Ant Design `Select` 的原始属性和表单协议：

- 默认启用 `showSearch`、`allowClear`、`virtual={false}`。
- 搜索统一匹配选项的可见 `label`，忽略大小写、空白和常见分隔符。
- 可同时匹配实体编码和名称；现有选项只需继续使用 `编码 · 名称` 作为 `label`。
- 选中后自动清空搜索词，但不改变表单字段值。
- 选项异步刷新时，只补回当前已选值对应的缓存选项，不把旧数据源的其他选项带到新的级联上下文。
- 所有原有 `onChange`、`disabled`、`loading`、`mode`、验证规则和表单提交结构保持不变。

状态、阶段、布尔值等固定枚举继续使用普通 `Select`，避免把所有下拉框都变成不必要的搜索控件。

## 数据流与防闪烁

实体选择器的输入只在浏览器内过滤已有候选项，不因输入每个字符触发网络请求。

商机总览、客户运营等服务端筛选页面在查询键变化时：

1. 筛选值立即保存在受控状态中。
2. React Query 保留上一份列表作为占位数据。
3. 新结果返回后原位替换，不卸载筛选区和主体内容。
4. 筛选候选项使用独立的未筛选数据源，避免选择一个条件后其他下拉框的选项被当前结果集反向裁剪。

级联选择只在上游值真正变化时清空直接依赖项，例如产品变化时清空产品版本；客户、项目名称和其他无关字段不重置。

## 覆盖范围

统一以下动态实体选择场景：

- 客户、商机、项目、产品、版本、模块、功能和需求。
- 产品负责人、项目经理、运营负责人、团队成员和技能。
- 商机总览、客户运营、实施驾驶舱和标准化中心的动态筛选项。
- 系统管理中来自接口的角色、团队和审计维度。

固定状态、阶段、优先级、时区等小型枚举不在本次改造范围内。

## 测试设计

组件级测试覆盖：

- 中文、英文大小写、编码和带空格文本的统一匹配。
- 用户选择后表单提交仍得到原始标量 ID。
- 加载期间选项数组暂时为空时，已选标签和值仍保留。
- 上游切换并清空值后，不保留旧数据源中的可选项。

页面级回归测试覆盖：

- 商机总览和客户运营选择筛选条件后，查询期间页面主体不被替换为空白加载态。
- 项目创建、商机编辑和标准化转换中的级联选择只清空直接下游字段。
- 保存请求携带用户最终选择的 ID。

最后运行前端完整测试和生产构建。
